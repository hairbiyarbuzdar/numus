# Numu — Bug Fixes Log

1. **Password field missing show/hide (eye) icon** — Fixed. Eye icon added to Login password field.

2. **Sign In button allows multiple clicks** — Fixed. Button now disables and shows a loading spinner while the request is in progress.

3. **Reset Password field missing eye icon** — Fixed. Eye icons added to New Password and Confirm Password fields.

4. **Redirected to Dashboard after password reset** — Fixed. Now redirects to Login instead.

5. **Send OTP / Resend OTP buttons allow multiple clicks** — Fixed. Buttons now disable and show a loading spinner while the request is in progress.

6. **Multiple Sign Up flow issues (eye icon, OTP button, redirect)** — Fixed. Eye icons added, OTP button now disables during request, redirects to Login after registration.

### Vendor

7. **Vendor registration doesn't enforce profile completion** — Fixed. Vendors are redirected to Complete Profile until approved, profile submission goes for Admin Approval, and product creation is blocked until approved.

8. **Submit Profile button visible before form is complete** — Fixed. Button stays disabled until all required fields are valid.

9. **Vendor profile submission not reaching backend / attachments not in cloud storage** — Submission-to-backend part: Fixed. Attachment storage: kept as-is (base64 in database), per decision.

10. **Product status field missing in Add Product form** — Fixed. Added a Status dropdown (Draft, Active, Out of Stock, Inactive, Archived). Drafts skip admin approval until published; Out of Stock stays visible to buyers but can't be purchased; Inactive/Archived are hidden from buyers immediately.

11. **Search and filter not working, pagination missing on My Products** — Fixed. The search box and Filters button were previously non-functional (unbound input, no click handler). `GET /products` now does server-side search (title/description/category), filtering (status, approval, type, category, price range), sorting and pagination. The page has a debounced search, a working filter panel with an active-filter count, sort dropdown, and pagination showing `1–10 of N` with rows-per-page and numbered pages. Callers that don't send paging params still get the old array response, so Marketplace and the admin views are unaffected. Added indexes on `products(category)` and `products(vendor_id, created_at)`; the status index needs `node src/db/migrate-product-status.js` re-run on existing databases.

12. **Save Product button allows multiple clicks** — Fixed. Button disables and shows a spinner while the request is in progress, guarded by a ref so two clicks in the same tick can't both get through.

13. **Input fields on My Products missing labels** — Fixed. All 19 controls (Add Product form, search, filters, pagination) now have persistent visible labels bound with `htmlFor`/`id`, matching the label style already used in Complete Profile. Placeholders that just repeated the label were changed to examples.

### Admin

14. **Auction status badges don't reflect the approval workflow** — Fixed. Badges read `auctionStatus` (the lifecycle field, seeded as `live` at creation) and ignored `approvalStatus`, so a new auction showed as Active before review. Added a shared `getAuctionDisplayStatus()` helper where approval gates the lifecycle: Pending until approved, then Active / Ended / Cancelled, or Rejected. Applied to the Auctions Manager badge, status filter (now includes Pending and Rejected) and Close/Cancel buttons, which no longer act on unapproved auctions, plus the Active Auctions counts on the admin dashboard and insights, which were counting unapproved auctions as live.

15. **View Details not opening the auction details modal** — Fixed. The eye icon opened a bids-only popup with no auction information. It now opens a full details modal: auction ID, title, vendor, category, derived status badge, starting price, current bid, bid increment, buy-now price, quantity, total bids, start/end dates, time remaining, created/submitted/approved-or-rejected timestamps, image gallery, description, winning bidder and order reference, and the full bid history. Pending auctions show a "not visible to buyers yet" notice and rejected ones show the rejection reason. Closes on Escape, the close button, or the backdrop.

16. **Vendor cannot edit auction details before bidding starts** — Fixed. There was no auction edit path at all: `PATCH /products/:id` only handles retail/wholesale columns, and My Live Auctions offered View / Close / Delete but no Edit. Added `PATCH /products/:id/auction` (title, description, category, image, starting price, bid increment, buy-now price, quantity, start and end time) and an Edit button that opens the auction form pre-filled with the current values. Editing is allowed only while the auction is still waiting to open — no bids placed and the start time still in the future. After that the auction is read-only and any attempt, from the button or a direct API call, returns "Auction details cannot be modified after bidding has started."; ended and cancelled auctions report their own reason. The lock is re-checked inside the UPDATE statement, so a bid landing mid-edit wins the race, and a vendor can only edit their own auctions. Each auction card now says either when bidding opens (details still editable) or why it is locked. Validation on save: prices and quantity above zero, buy-now at least the starting price, start time in the future, end time after the start. Approval status is left untouched — an edited auction keeps whatever approval it had. Related: bids were accepted before the auction start time, which would have let a buyer freeze a vendor's auction early — `POST /products/:id/bids` now rejects those, and the buyer's Auctions page and product details show "Bidding opens …" with an Upcoming badge instead of a bid box until the auction starts.

17. **Auctions page missing pagination, search and filtering** — Fixed. The admin Auctions page pulled every product into the browser through the shared context and filtered client-side on title + vendor with no paging, so the table grew without limit. It now uses the same server-side listing as My Products: `GET /products?productType=auction` with search, filters, sorting and paging done in SQL, a debounced search box, a Filters panel with an active-filter count, "Showing 1–10 of N" with rows-per-page (10/25/50) and numbered pages, a loading overlay, and a retry on error. Search matches auction ID, product name, description, category and vendor name — `id` and `vendor_name` were added to the API's search clause, so `GET /products` search improves everywhere. New API filters: `auctionState` (pending / active / rejected / ended / cancelled), which resolves the derived admin status across `approval_status` and `auction_status` the same way `getAuctionDisplayStatus()` does on the client, and `dateFrom`/`dateTo` with `dateField` (created date, auction start, or auction end) taking epoch milliseconds so day boundaries follow the admin's own clock. Added sorts for ending soonest/latest and highest/lowest bid. The category dropdown now asks for options scoped to auctions (`GET /products/filter-options?productType=auction`) instead of listing retail categories that can never match. Close / cancel / delete reload the current page afterwards, and the details modal keeps a snapshot of the row so filtering or paging underneath it can't yank it closed. Indexes added for the new queries — existing databases need `node src/db/migrate-auction-filters.js` (or `npm run migrate:auction-filters`).

18. **Vendor dashboard fetched every module's data on login, with no per-module loading states** — Fixed. `pages/_app.tsx` wraps every page in eight providers for every role, and two of them fetched on mount: `ProductProvider` pulled the product list (unpaginated, with a bids query per auction row) and `UsersProvider` pulled the entire user table — the latter on vendor and buyer sessions too, even though `GET /auth/users` is admin-only data. Both ran again on every refresh, on every page, whichever module was open. Both contexts are now lazy: they fetch nothing on mount and expose `loaded` / `ensureX()` / `refreshX()`, so a module loads its data when it is opened and reuses the cache afterwards. `UsersProvider` is additionally gated to admin sessions, so vendors and buyers never request the user table at all. The caching rules (fetch once, collapse concurrent callers into one request, stay cold after a failure so the next attempt retries, drop the cache when the signed-in user changes) live in `utils/lazyFetch.ts` and are covered by a 15-case contract test. Per module: Products already fetched its own paginated page, and no longer also pulls the full list; Auctions, Marketplace, product details, buyer auctions, approvals, admin products, admin users, insights, notifications centre, listings and the admin dashboard each load on open; the admin Auctions page was already self-fetching from #17. Every one of them now shows a skeleton (`components/Skeleton.tsx`: table rows, cards, tiles, stat tiles, lines) instead of an empty table or a false "no results" while loading — vendor Products shows skeleton rows on first load and keeps the spinner overlay for refetches, and product details shows a skeleton rather than "Product is unavailable" before the catalogue arrives. Notifications still load once per session for the navbar bell. Known gap, unchanged here: vendor Orders reads from localStorage rather than the backend `/orders` route, so it has nothing to defer — it now shows a loading state for consistency, but wiring it to the API is its own ticket.
